- Going to build on yesterday by using backup registers to increment day count by 1 on every interrupt/wake cycle.
	- PWR_CR1 register, bit 8 lets us enable accessing the backup registers
		- This needs to be done on every wakeup as access is automatically disabled on a reset
	- The U0 has 9 32 bit backup registers (which can be tamper proofed) TAMP_BKPxR, x = [0,8]
		- I have no use for tamper protection so I will keep it disabled
		- The backup registers are part of the RTC so I will enable that in CubeMX
	- ```
	    //__HAL_PWR_GET_FLAG(PWR_FLAG_WUF7); high if woke up from wakeup pin 7
	    HAL_PWR_EnableBkUpAccess();
	    uint32_t dayCount = HAL_RTCEx_BKUPRead(&hrtc, RTC_BKP_DR0); //init value = 0
	    dayCount++;
	    HAL_RTCEx_BKUPWrite(&hrtc, RTC_BKP_DR0, dayCount);
	    HAL_PWR_DisableBkUpAccess();
	  ```
		- Backup register default value is 0 so I can just increment right from the start
		- If this test is successful I will only increment if woke up from wakeup pin 7
		- I was planning on using SWD to see if dayCount is properly incrementing but it doesn't seem to latch back on after wakeup so I will read through section 38.2.6 in the reference manual to learn how to debug in low power modes. Although I can simply omit going to shutdown mode by instead placing everything in a loop, I felt this would be useful to learn as there's a decent chance it'll come in handy in the future, and will emulate the intended function more closely than the loop.
			- To do this it emulates the low power mode by still going into the low power mode but keeps being able to clock and power
			- To do this I can set DBG_STANDBY bit in DBGMCU_CR register to debug in shutdown mode. Using `HAL_DBGMCU_EnableDBGStandbyMode();`
			- I can also disable certain functions like Timers and RTC but I have no use to do that
		- It worked and latched back on. But it started at dayCount = 3, I assumed since the debugger is downloading back the code. But just to confirm I removed the increment and indeed it does start at 0.
	- Now only incrementing on the RTC interrupt
		- I only incremented dayCount if PWR_FLAG_WUF7 was SET but the dayCount was 3 from the beginning meaning that while flashing and waiting the initial code ran multiple times from POR and incremented each time.
			- Going through with the debugger, HAL_PWR_EnableWakeUpPin(PWR_WAKEUP_PIN7_LOW) makes WUF7 high I assume because the pin was not monitored before this line and defaulted to 0. As it was 0 and I enabled an interrupt on a LOW signal it instantly raises the flag. And when we check for the flag later it's still high.
			- I couldn't simply clear the flag after since this line runs every time and would clear a real flag. The long term solution is that I only initialize the RTC and thus run this line on POR, but for now I check for the flag before and if it was 0 I clear it after enabling the pin.
			- With that it works great.
